진행사항.txt (2026-10-02 기준, 녹음파일 저장 반영)

지금까지 목업 프로토타입 위에서 실제로 구현된 부분을 파일별로 정리한다.


1. meetalign/models.py
----------------------
- Team: 팀 (name, members — User와 M2M)
- Meeting: 회의 (team FK, title, created_at, ended, deadline, host, transcript, record, processing_status)
  transcript는 모든 녹음의 전사를 순서대로 이은 것, record는 그 전사를 정리한 회의록이다.
  host는 주최자(회의를 만든 사람, 기본값). 익명 질문함(inbox)과 답변(answers)은 주최자만 쓸 수 있다.
  host가 비어 있는 옛날 회의는 팀원 누구나 쓸 수 있게 열어둔다.
  deadline은 마감일(DateField, 선택). is_due_tomorrow 속성이 마감 하루 전이면 True.
  회의 목록에 [D-1 마감], 회의 상세에 마감 안내문을 띄운다. 실제 알림 발송은 없음.
  record는 회의록 텍스트 저장 자리(TextField). 지금은 값을 채우는 기능이 없고,
  STT/LLM 작업에서 채움. summary 화면은 이 값을 그대로 보여주거나 없으면 안내문을 띄움.
  recording은 실제로 업로드된 녹음파일을 저장하는 FileField. STT/LLM 처리는
  아직 없고, 파일을 서버에 실제로 남기는 것까지만 구현됨.
- Question: 익명 질문 (meeting FK, text, answer) — 작성자는 저장하지 않는다.
  채팅창에서 익명으로 보낸 질문과, 그 질문에 대한 답변(호스트 쪽)을 담는다.
- CheckQuestion: 이해도 검증 질문 (meeting FK, text, order)
  회의록(record)이 생긴 뒤 이해도 검증 화면을 열 때 처음 한 번 만들어진다. 회의록이 없으면 질문을 만들지 않는다.
  지금은 LLM 연동 전이라 고정 문항 2개("핵심 결정 사항은?", "내가 맡은 다음 할
  일은?")가 화면 처음 열릴 때 자동 생성된다. 나중에 LLM이 실제로 질문을 내도록
  바뀔 자리.
- Answer: CheckQuestion에 대한 팀원별 답변 (question FK, user FK, text)
  같은 질문이라도 사람마다 답을 따로 저장해야 "누구와 누구가 다르게 이해했는지"
  비교할 수 있어서, question+user 조합을 unique_together로 묶어 1인 1답변만
  남도록 했다. (Question.answer는 답변자가 하나뿐이라 이 용도로는 못 씀 — 그래서
  별도 모델로 분리함)


2. meetalign/views.py
----------------------
- index / signup / login_view / logout_view
  Django 기본 인증(UserCreationForm, AuthenticationForm)으로 실제 가입·로그인·
  로그아웃이 동작한다. 예전엔 current_user()가 항상 가장 먼저 만든 유저를
  반환하는 가짜 로그인이었는데, 지금은 완전히 제거하고 request.user를 쓴다.

- team_join / meeting_list / meeting_create / meeting_detail / meeting_result /
  chat / inbox / summary / answers / understanding
  전부 @login_required 적용됨. 로그인 안 하면 로그인 페이지로 리다이렉트.
  팀/회의 멤버십 체크(_team, _meeting 헬퍼)도 request.user 기준으로 동작.

- understanding (이해도 검증)
  CheckQuestion이 없으면 고정 문항 2개를 자동 생성하고, POST로 들어온 답을
  사용자별로 저장/수정(update_or_create)한다. 재제출하면 덮어쓰기(중복 생성 안 됨).

- _find_discrepancies (불일치 탐지 틀)
  질문별로 팀원 답변이 서로 다르면 묶어서 understanding 화면 하단에 보여준다.
  지금은 문자열 비교(strip 후). 나중에 LLM 의미 비교 + 회의록 대조로 교체할 자리.

- meetalign/services.py (LLM 연결 지점)
  OLLAMA_MODEL 환경변수가 있으면 로컬 Ollama(OLLAMA_URL, 기본 http://127.0.0.1:11434)를 호출한다.
  회의록(record)이 있을 때만 질문 생성과 회의록 기반 답변을 하고, 없거나 환경변수가 없으면 기존
  가짜 동작을 그대로 쓴다. Ollama 연결이 실패하면 가짜 문항 또는 안내 문구로 대체된다.
  is_consistent(불일치 비교): 답변이 글자까지 같으면 일치. 다르면 OLLAMA_MODEL이 켜져 있을 때 회의록을 근거로
  LLM이 같은 뜻인지 판단한다. LLM이 꺼져 있거나 실패하면 문자열이 다르면 불일치로 본다.
- LLM 문맥 길이: OLLAMA_NUM_CTX 환경변수 (기본 16384). 기본 설정에서는 약 1만 자 이상 전사본의 앞부분을 못 읽어서 올렸다.
- meetalign/services.py의 summarize (회의록 요약)
  OLLAMA_MODEL이 켜져 있으면 전사본을 [안건], [결정 사항], [할 일] 형식으로 정리해 회의록(record)에 넣는다.
  꺼져 있거나 실패하면 전사 원문을 그대로 쓴다. 전사 원문은 transcript 필드에 따로 저장한다(0008).
  summary 화면에서 '전사 원문 보기'로 원문을 확인할 수 있다.
- Recording: 회의 하나에 녹음 여러 개 (file, transcript, status, created_at). 마이그레이션 0011이 기존 단일 녹음을 옮긴다.
  녹음을 올릴 때마다 새 행이 생기고, 모든 녹음이 끝나면 전사를 이어 붙여 회의록을 다시 만든다.
  회의 하나의 처리 상태는 하나라도 처리 중이면 처리 중, 아니면 완료(모두 실패면 실패).
- meetalign/services.py의 transcribe (STT)
  MLX_WHISPER_MODEL 환경변수가 있을 때만 로컬 mlx-whisper로 녹음을 한국어 전사한다.
  녹음을 올리면 백그라운드 스레드에서 전사가 진행된다(meetalign/tasks.py). 상태는 processing_status
  (processing/done/failed)에 기록되고, 결과 화면이 진행 중에는 5초마다 새로고침한다.
  녹음을 올리면 전사 결과가 meeting.record에 저장된다(지금은 전사문 그대로, 요약은 다음 단계).
  실행 방법 (로컬 모델 qwen2.5:7b 기준, 맥북 16GB에서 답변 약 2~3초):
    ollama serve                      # 별도 터미널, 실행 상태 유지
    cd APL_04 && OLLAMA_MODEL=qwen2.5:7b MLX_WHISPER_MODEL=mlx-community/whisper-large-v3-turbo ../.venv/bin/python manage.py runserver
  STT 준비: brew install ffmpeg && ../.venv/bin/pip install mlx-whisper (모델은 첫 전사 때 자동 다운로드, 약 1.6GB)

- chat (대화창)
  mode=anon이면 Question을 익명으로 생성, mode=llm이면 고정된 가짜 응답 문자열을
  반환한다. 실제 LLM 호출은 아직 없음.

- meeting_detail
  업로드된 녹음파일(request.FILES)을 meeting.recording에 실제로 저장한다.
  STT/LLM 처리는 아직 없음 (다음 작업 대상) — 지금은 "파일이 서버에 실제로
  남는다"까지만.


3. meetalign/apps.py
----------------------
default_auto_field를 BigAutoField로 명시했다. 이게 없으면 Django 버전에 따라
자동 PK 타입 판단이 달라져서 makemigrations가 불필요한 변경을 계속 감지하는
문제가 있었음 (0001이 BigAutoField로 생성돼 있었는데, 0002에서 이 설정 없이
작업하다 보니 AutoField로 생성돼서 불일치가 생겼었음 → 0003에서 수정).


4. meetalign/migrations/
----------------------
- 0001_initial.py: 최초 모델(Team, Meeting, Question)
- 0002_checkquestion_answer.py: CheckQuestion, Answer 모델 추가
- 0003_alter_answer_id_alter_checkquestion_id.py: 위 두 모델의 PK 타입을
  BigAutoField로 통일 (apps.py 수정에 맞춰 스키마도 맞춤)
- 0004_meeting_recording.py: Meeting에 recording(FileField) 추가
- 0005_meeting_record.py: Meeting에 record(TextField) 추가

※ 주의: 새 마이그레이션 받으면(git pull 등) 서버 켜기 전에 꼭
  `python manage.py migrate` 먼저 돌릴 것. 안 돌리면 기존 DB 파일
  (db.sqlite3)에 새 필드가 없어서 "no such column" 에러가 난다.
  (manage.py test는 매번 새 DB를 만들어서 이 문제가 안 생기지만,
  실제로 서버 켜서 쓸 땐 기존 DB 파일을 그대로 쓰기 때문에 발생함)


5. meetalign/templates/meetalign/
----------------------
- index.html / login.html / signup.html
  실제 로그인 상태(user.is_authenticated)에 따라 화면이 분기되고, 가입/로그인
  실패 시 에러 메시지가 뜬다.
- understanding.html
  고정 버튼("제출 — 동작 안 함")이었던 걸 실제 폼으로 바꿔서 질문별 답변이
  저장되고, 다시 들어오면 저장된 답이 미리 채워진다.
- meeting_detail.html
  업로드된 녹음파일이 있으면 파일명을 화면에 표시한다.
- summary.html
  고정 가짜 요약 문구 대신 meeting.record 값을 보여주고, 없으면 안내문을 띄운다.
- 그 외(chat, inbox, meeting_result, meeting_list, meeting_create,
  team_join) 템플릿은 아직 목업 단계 그대로 — 화면 흐름과 뼈대만 있고 실제
  콘텐츠(LLM 결과 등)는 가짜/고정값이다.


6. setting/settings.py / setting/urls.py
----------------------
- settings.py: LOGIN_URL, LOGIN_REDIRECT_URL 추가 — @login_required가 비로그인
  사용자를 로그인 페이지로 보낼 수 있도록. MEDIA_URL, MEDIA_ROOT 추가 — 업로드된
  녹음파일이 실제로 저장될 경로.
- urls.py: 녹음 파일은 더 이상 /media/로 공개하지 않는다. 대신 /meetalign/meetings/<id>/recording/ 이
  로그인하고 회의 멤버인 사람에게만 파일을 준다.
- 보안·입력 검증
  로그인 후 이동(next)은 같은 사이트 주소만 허용한다(외부 주소 차단).
  마감일 형식이 틀리면 회의를 만들지 않고 안내를 띄운다.
  녹음은 허용 형식(mp3, m4a, wav, ogg, webm, mp4, flac)과 500MB 이하만 받는다.
  종료된 회의에는 녹음 업로드와 익명 질문을 막는다.
- 배포 설정: SECRET_KEY(DJANGO_SECRET_KEY), DEBUG(DJANGO_DEBUG, 기본 1=켜짐),
  ALLOWED_HOSTS(DJANGO_ALLOWED_HOSTS, 쉼표 구분, 기본 localhost,127.0.0.1) 환경변수로 분리.
  배포할 때는 DJANGO_DEBUG=0 과 실제 SECRET_KEY를 꼭 설정할 것.

설계 대조로 맞춘 내용
----------------------
- 회의 종료 → 3.5 '생성된 질문에 대한 답변' (이해도 질문 답변 화면, understanding)
- 3.6 '개별 이해도 검증' 결과 화면 (verification): 답변이 엇갈린 질문 목록. 답변 화면에서 링크로 이동
- 익명 질문 답변 화면(answers)은 주최자(=팀장)만 사용. 회의 상세와 익명 질문함에서 진입
- 결과 화면(3.3.3): 회의록 생성이 끝나면 회의록 다운로드 버튼 (record.txt, 회의 멤버만)
- 메인 화면: 내일 마감인 회의 배너 (컷 11)
- 설계에서 뺀 것: 3분 이내 완료 목표(팀 결정), 제안자가 질문 직접 등록(LLM이 생성하기로 함)

후속 보완
----------------------
- 이해도 질문은 (회의, 순서) 조합이 유일하도록 DB 제약을 걸었다(마이그레이션 0010). 동시에 만들어져도 하나만 남는다.

- 녹음은 여러 개를 올릴 수 있다(마이그레이션 0011). 이전 녹음은 지우지 않고, 전사를 올린 순서대로 이어 회의록을 만든다.

----------------------

  관리하는 개인 작업본이라 PR 없이 바로 main에 커밋한다.

  2단 분할 레이아웃, 로그아웃 상태 랜딩 히어로, 파비콘, 빈 상태 아이콘,
